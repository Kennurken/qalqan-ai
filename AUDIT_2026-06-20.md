## Найденные проблемы + пути фикса (НЕ фиксить пока)

### B1 — Мёртвый in-memory reports-store на serverless (P2, было в первом аудите)
- **Где:** `api/index.py:756` `_reports_memory` + `/report` endpoint (логика `auto_blocked`).
- **Суть:** на Vercel каждый инстанс холодный → счётчик жалоб не накапливается, файл-запись в read-only FS молча падает (`except: pass`). `auto_blocked` (≥10 жалоб) почти не срабатывает. Источник правды — Supabase, in-memory путь вводит в заблуждение.
- **Фикс:** считать жалобы из Supabase (`get_community_stats(domain)`), как уже делает `/vote`. Удалить `_reports_memory`/`_save_reports`/`_load_reports`.

### B2 — Валидатор URL пропускает decimal/hex-IP (low severity)
- **Где:** `api/index.py` `CheckRequest.validate_url` (`_PRIVATE_IP_RE`).
- **Суть:** `http://2130706433/` (= 127.0.0.1 в decimal) проходит входной валидатор (200), т.к. regex строковый. **НЕ эксплойт** — `domain_intel._is_internal_host` декодирует decimal/hex и блокирует сокет (проверено: domain_details=False, подключения нет). Но edge-валидация неконсистентна.
- **Фикс:** в `validate_url` добавить `ipaddress`-проверку: если host — число/0x-hex, декодировать в IP и отклонять private/reserved. Defense-in-depth на входе.

### B3 — ml/ директория без весов (P0-1 честность, частично закрыто)
- **Где:** `ml/qalqan_model/` — есть `config.json`, `tokenizer.json`, `training_metrics.json` (заявляет accuracy 0.9976), но **нет** `model.safetensors`/`.bin`.
- **Статус:** лендинг уже переименован в «6-уровневый» (честно). Но если жюри откроет `ml/` — увидит метрики без модели.
- **Фикс:** либо (а) `ml/README.md` пометить «experimental/offline, веса не в гите», убрать/перегенерить `training_metrics.json`; либо (б) реально обучить sklearn/transformer (юзер отложил ML).

### B4 — index.py монолит ~2046 строк (P2 maintainability)
- **Где:** `api/index.py` — роуты + inline `_GRAPH_HTML`/`_PARTNERS_HTML`/`_DASHBOARD_HTML` + демо-данные.
- **Фикс:** вынести оставшиеся HTML-константы в `templates.py`; роуты — в `routes/` (APIRouter: check, telegram, goszakup, feed, partner, dashboard). Цель — index.py ~80 строк сборки.

### B5 — Нет `/sms` алиаса (косметика)
- **Суть:** SMS-текст обрабатывается через `/check-text` (бот `/sms` его и зовёт), но отдельного `/sms` нет.
- **Фикс:** добавить `POST /sms` алиас → `/check-text` + `extract_urls()` для извлечения ссылок (уже есть в `phone_sms.py`).

### B6 — Манифест отдаётся из CDN-кэша 24h (косметика)
- **Где:** `/manifest.webmanifest` `Cache-Control: max-age=86400`. После смены `start_url` на `/m` CDN ещё отдаёт `/`.
- **Фикс:** снизить TTL до ~300с или добавить версионный query; не критично (самообновится).

### B7 — Нет тестов на бот-хендлеры и voice/transcribe (покрытие)
- **Суть:** 113 тестов покрывают сервисы/эндпоинты, но бот-диспетчер (callback/voice/dispatch) и `transcribe_audio` (Groq) — только косвенно.
- **Фикс:** добавить юниты на `dispatch()` с мок-update (voice/callback/text), мок httpx для Groq.

## Как масштабировать (архитектурно)

1. **Бэкенд → VPS/контейнеры:** FastAPI под gunicorn+uvicorn workers (или k8s при росте). Уносит keep-warm/cold-start проблему.
2. **БД:** индексы на `check_logs(created_at, verdict, domain)`; партиционирование по дате; при росте — выделенный Postgres (Neon/RDS) + read-replica для дашборда.
3. **Кэш:** Upstash → dedicated Redis cluster; CDN для статики (Vercel уже edge).
4. **Очереди:** вынести тяжёлое (AI, Whisper-транскрипция, PDF) в фоновые воркеры (Celery/RQ/Cloud Tasks) — `/check` отвечает мгновенно.
5. **ML-сервинг:** отдельный inference-сервис (ONNX Runtime/Triton), горизонтальное масштабирование.
6. **Аналитика:** фиды/логи → warehouse (ClickHouse/BigQuery) под дашборд регулятора при больших объёмах.
7. **Observability:** Sentry (ошибки) + Prometheus/Grafana (метрики) + структурные логи.
8. **Data-pipeline:** scheduled ingestion фидов (OpenPhish/URLhaus/партнёры) → дедуп → bloom-filter индекс.
